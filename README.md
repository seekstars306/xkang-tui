# 小康业务与本机助手

2.0 将公司业务排障移到服务端。客服端只接收业务答案、核验状态和进度；本机办公使用独立入口与会话。

## 信息边界

客服工作需要的姓名、电话、证件、订单号、金额和状态完整展示，不自动掩码。号码按字符串处理，不丢失前导零或长数字精度。

公司代码、方法名、库表字段、SQL、源码目录、内部技术地址、原始日志、工具结果和思考过程只在服务端取证和审计。业务规则可以用通俗语言解释。公开答案的依据使用业务描述，完整出处通过服务端证据编号关联。

员工令牌不能直接访问 `/mcp`、`/codegraph` 或内部技能和工具列表。管理员可通过独立鉴权读取内部证据。`/v1/chat/completions` 是隔离的本机模型通道，不装载公司业务工具。

## 开发与启动

```powershell
npm install
npm install --prefix server
npm run build
npm run --prefix server build
npm run --prefix server start
```

服务端配置位于受忽略的 `server/.env`。业务会话、内部证据、复核记录与员工身份存入服务端 SQLite。共享执行核心位于 `packages/agent-core`，客户端和服务端构建都会先编译它。

核心模型使用 `GEMINI_MODEL=gemini-3.8-flash-high`，通过 `GEMINI_REASONING_EFFORT=high` 显式开启思考；`default` 仅用于还原不传思考参数的对照。调查、复核和模型转发均使用该设置。模型名称中的 `high` 不替代请求参数。审计记录思考用量、缓存用量与中转回报的总 token；未回报用量不代表免费。

```powershell
# 正常业务入口（首次使用绑定员工授权）
xhang
xhang --tui

# 独立本机助手，不读取公司业务会话
xhang --local
xhang --local --tui
```

业务网页默认端口 8611；本机网页默认端口 8612。两者只监听回环地址。开发预览使用 `npm run web`。

业务接口位于 `/agent/sessions`：创建、列举、读取、删除本人会话，提交问题、回答业务澄清。服务端按稳定员工身份检查归属，不接受客户端指定其他所有者。

## 复核与历史迁移

业务答案发布前进行独立事实和开发信息保密复核。首次未通过最多补查三轮、修订一次，再复核一次；补查计入原有 50 轮预算。失败时只发布能够核验的业务信息和待确认事项。完整历史不随模型上下文压缩而删除。

每次复核先查找缺失前提、反例和过度承诺，通过后再核对逐句引文。服务端高思考配置默认使用 `ANSWER_REVIEW_TIMEOUT_MS=180000`，两步及格式重试共用180秒总时限；可设为60000至300000毫秒，超时仍降级。内部复核的辅助字段可忽略，必要判断字段仍须完整；格式不合规时每步最多重新检查一次，错误响应仅在服务端留存。公开字段不因此放宽，完整业务号码也不改写。

网页、TUI、复制内容和刷新回放使用同一份公开结果，状态为“已复核 / 需人工核实 / 未复核”。“已复核”不等于人工确认。

旧本地业务会话先上传服务端并校验哈希，得到回执后才替换为公开历史并清理旧 SQLite/WAL 中的应用副本。失败保留唯一原文但不开放回放，提示迁移未完成。旧回答不会自动当作可信证据。外部人工副本不在自动清理范围内。

本地业务公开缓存为 `~/.xkang/business-sessions.db`，本机办公记录为 `~/.xkang/local-sessions.db`。员工配置不再保存公司代码目录。

## 验证

```powershell
npm test
npm run typecheck
npm run --prefix server typecheck
npm run typecheck:test
npm run test:integration
npm run test:ui
npm run ui:demo
```

集成测试启动独立服务端和审计库，关闭业务代码同步，仅使用只读业务工具；员工原始工具访问必须被拒绝。网页测试使用隔离的 Google Chrome、虚构业务数据和真实公开接口，验证完整业务字段、开发信息不下发、复制与刷新一致。

`tests/eval/business_acceptance_cases.json` 预登记 20 道业务题。正式质量验收必须两版各运行三轮并逐次核验证据，不使用固定人数或关键词评分。评测原文、审计与截图只保存在被忽略的报告目录，不能随客户端分发。

模型诊断使用 `node --import tsx scripts/eval/model_ceiling.ts evidence <新输出目录>` 对照相同证据，使用 `workflow` 对照五类完整流程；第四个参数可选择配置，如 `flash-high`，单配置串行运行。配置包括 Flash 默认/high 和本地中转的 K3、GLM 5.3、GLM 5.3 Flash、DeepSeek V4.1 Flash，仅用于评测，不改变生产模型。参考评分与被测输入分离，正常结束、诚实未解决和答错分别统计。

## 候选构建与正式分发

```powershell
npm run build:exe
# 验收通过后才允许：
npm run build:exe -- --publish --report <验收目录>
```

缺省只生成 `out/xhang-2.0.0-candidate.exe`，不替换正式分发包。打包使用客户端文件白名单，排除服务端、项目记忆、评测材料、数据库和环境凭据。

正式发布检查 20 题×3 轮×2 版本的完整证据评分、源码冻结哈希，以及隐私、业务字段、迁移、Chrome 和 EXE 验证。新版须至少 54/60 次完整可用、59/60 次正常结束，严重误导为零。任何缺项都阻止发布。回滚保留员工原始工具访问限制，必要时暂停业务入口，不能恢复原文下发。
