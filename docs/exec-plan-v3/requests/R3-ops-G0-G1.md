## 一、需要一次停机窗口（约 30 分钟）

**要做什么**：重启一次服务端（`D:\web_pro\xkang-tui\server`，端口 8600），让"代码同步不再执行 `git reset --hard`"这一改动生效。

**不需要做什么**：**不再需要更换代码镜像。** 镜像换装已经在 10-12 完成（保留根目录、切换子目录），现在 17 个仓库都是完整克隆、工作区干净。

**为什么这件事有风险**：当前服务端的定时同步是**开着**的（`CODE_SYNC_ENABLED=true`，间隔 10 分钟）。它在 `git pull --ff-only` 失败之后会执行 `git reset --hard`，**会抹掉镜像里任何未提交的改动**。现在镜像恰好干净，所以暂时无害，但这只是巧合，不是已经修好。改完之后这条路径会变成"跳过并记录"，不再动文件。

**怎么执行**：具体步骤（含前置检查、窗口内顺序、回滚路径）已经写成 `tests/eval/reports/exec-v3/restart-for-s1-runbook.md`，可以在窗口内逐条照做。回滚方式是退回原来的 `dist` 启动，所以窗口开始前会先把旧 `dist` 备份一份。

**需要你提供**：一个 30 分钟的时间段，以及确认当前 8600 这个实例（`node … dist/index.js`，父进程是 `npm start`）就是唯一在跑的那一个。

> 2026-10-14 实测佐证：8600 当前由 **PID 33700** 监听（2026-10-13T07:21:00Z 启动，记录在 `server/data/service-lifecycle.jsonl`），`netstat` 未见其它进程占用 8600；`CODE_SYNC_ENABLED=true`、`CODE_SYNC_INTERVAL_MINUTES=10`。窗口开始时请以当时的实测 PID 为准再核对一次。

## 三、现网制品标识怎么取

需要知道每个线上服务的 war/jar 的 **sha256** 或**镜像摘要**怎么导出。

原因：`skt_cxy` 的 pom 里没有 build-info 类插件，**jar 哈希没法自动反查提交**，所以只能由人给出"制品标识 + 提交号"两样才能判定线上版本。这一步和开发那边的版本清单是同一件事，如果你和开发同学一起给最快。
