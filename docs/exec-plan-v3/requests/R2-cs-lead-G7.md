# 请求（发给客服负责人）· G7

> 用途：导出一批真实工单，用来校准客服助手到底能答多少、答得对不对。
> **请直接转发。**

---

## 需要什么

**60 条以上**近期真实工单，我们会从中筛出 **30～40 条**用于摸底。

## 导出格式

表格或 Excel 都行，列名照下面这个来：

| 列名 | 说明 | 必填 |
|---|---|---|
| `ticket_no` | 工单号 | 是 |
| `created_at` | 工单创建时间 | 是 |
| `business_line` | 业务线：机票 / 酒店 / 火车票 / 打车 / 发票 / 短信通知 / 支付 / 其他 | 是 |
| `question` | **客服当时的原始提问原文** | 是 |
| `attachments` | 附件（截图等）的文件名，或直接附上文件 | 有就填 |
| `handling` | 客服当时的处理过程与结果 | 是 |
| `outcome` | 最终结论：已解决 / 转研发 / 未解决 / 其他 | 是 |
| `core_demand` | **一句话说明这个工单到底要问什么** | 是（也可以后补） |

## 两个要点

**第一，请不要做脱敏。** 姓名、电话、证件号、订单号、金额都请**保留原样**——这些正是要核对的数据，脱敏之后就没法验证答案对不对了。

数据只会放在本机一个不进代码仓库的目录里。不会进代码提交，不会写进日志，不会出现在对外报告里。我们的所有汇报里只用匿名编号和数量。

**第二，`core_demand` 这一栏最关键。** 我们要用"是否回答了核心诉求"来算覆盖率——如果助手答的是另一个问题，哪怕答得对也不算数。这一栏**一句话就够**，不需要写长，可以由我们起草后请你们确认或改写。

## 关于偏斜

如果近期工单在话题上比较集中在某几类（客服台常有这种情况），**请照实导出，不要为了凑多样性特意挑题**。

偏斜本身就是要报告的结果——它直接决定这个助手在实际使用里能覆盖多少问题。
