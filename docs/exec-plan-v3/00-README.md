## 5. 指标定义（所有阶段共用）

**工单级结局**（每个工单的每次运行，只能选一个）
- `delivered`：给出了"已确认"内容（`reviewStatus=reviewed`，或部分发布且包含至少一条已核实的业务结论）。
- `unresolved_honest`：只给出"待核实 + 已查到的事实"，且这些事实全部正确，没有误导。
- `wrong`：交付内容含错误（业务结论、附加断言或话术任一错误）。
- `severe`：严重误导——错误的资金处理建议、虚构助手已执行的动作、可能误阻断业务的结论、掩盖通知外发风险、或泄露凭据/内部信息。

**指标**
- 覆盖率 = 回答了预先标注的"核心诉求"的工单数 / 工单总数。只返回订单号不算回答。
- 交付正确率 = 交付工单里整答全对的数量 / 交付工单数。整答 = 结论 + 附加断言 + 话术，任何一处错就算错。
- 严重误导率、违规率（凭据、内部信息）：必须为 0；报告时给单侧 95% 上界。
- 时间：首轮 15 分钟内完成的比例（主指标）；追加 5 分钟后完成的比例（单独报告）；P50/P90。
- 成本：只报 token（输入、输出、思考、缓存），不报金额。
- 同一工单的追问、改写、重复运行**不增加独立样本**。
- 统计：二项比例用单侧 95% Clopper-Pearson；摸底报告同时给 Wilson 双侧区间。库见任务 S5。

**银标签与金标准**：模型打的分是银标签；开发核对过的是金标准。报告里分开统计，银标签的结论只能说"诊断"。

## 9. 术语

- **复核（review）**：回答发布前由模型做的两步检查——反证（找逻辑漏洞）和引文（逐句核对原文引用）。
- **工单**：一个独立的客服问题，含上下文和附件。
- **核心诉求**：开发/客服事先标注的"这个工单到底要问什么"，覆盖率据此判定。
- **镜像**：`D:\skt_project`，服务端读取业务代码的本地副本。
- **三档版本**：已核准 / 推定 / 未知（决策 D2）。
- **银标签 / 金标准**：见 §5。
- **特性开关**：新行为默认关闭，由环境变量打开，便于灰度和回滚。
