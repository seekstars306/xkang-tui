# 09 G3 预算单 ③：规则消融对照（定向补查到底有没有用）

第 5 项要花钱，先出预算单等批准。**批准之前不启动任何付费调用。**

## 1. 要回答的问题

第 4 项往两处加了「怎么去查」的通用步骤：排查期提示词的四步（l2，order 86）和复核修订轮被点名时的
【定向补查】四步（`REVISION_DIG_PROCEDURE`，登记为 `general_procedure`）。

要回答的是：**它有没有让模型真的去读判定分支**。判定看工具调用分布，不看措辞。上一次的教训是——
「没证据就写未定位」这条纪律生效了（不再编造成因），但工具调用分布与改动前逐项相同，判定分支一次没读到。

## 2. 测什么、怎么测

同一道题（酒店重复开票，开发集/回归用例，不进留出集），同模型同档位同冻结源码哈希，串行：

| 臂 | 设置 | 次数 |
|---|---|---|
| ON | 两处步骤都在（现状默认） | 3 |
| OFF | 关掉 `REVISION_DIG_PROCEDURE` 追加与 l2 四步（仅实验用开关） | 3 |

每次记录：工具调用序列与分布（是否 `read_file_lines` 到写入方法、是否读到去重/幂等分支、是否 `company_db_query` 数入口、
是否解码时间字段）、耗时、模型调用次数、token、最终答案的成因句形态、复核结论与 claims。

**开关（2026-10-16 已落地，见第 3.1 节）**：只拦"注册 / 追加"这一步，源码文本原样保留——两段文本都按逐字 anchor
登记在 `tests/eval/frozen-rules.json`，删文本会让守门测试变红。

## 3. 成本

锚点来自 2026-10-16 的同题实测（`_retest/full-ticket-run-…/result.json`）：单次 364 秒 / 42 次模型调用 /
输入 1,230,618 token / 输出 17,156 / 思考 21,043。

| 情形 | 估算 |
|---|---|
| 6 次 × 实测锚点 | **≈ 7.4M 输入 token** |
| 输入翻倍（补查带来更多轮次与更长证据包） | ≈ 15M |

**申请 7.4M，硬上限 23.4M。** 纪律照旧：只计 token（中转无价格接口），以 `usage-ledger.jsonl` 逐调用记录为权威，
单任务超 10M 立即暂停请示；全部串行、每次调用写台账。

## 3.1 开关实现（2026-10-16）

- `server/src/agent/rule_layer.ts` 的 `ruleLayerEnabled()`：只认一个 env `RULE_LAYER`，`off` / `0` / `false` 为关闭，
  其余（含未设置）为开启。**原计划的两个 env 合并成一个**：分两个会让对照臂只关掉一半却不报错。
- 关闭时同时作用于两处：排查期 l2 的四步 section 不注册（`investigation_prompt.ts` 构造器）、
  复核修订轮的【定向补查】不追加（`review.ts` 三处 `needsDirectedFollowup` 全部与开关做与运算）。
- 留痕与自证（写进 `manifest.json` / `result.json`，不靠记忆）：
  `flags.ruleLayer`（本次自变量取值）、`promptHasRepeatSteps`（OFF 臂应为 `false`）、`digFollowups`（OFF 臂应为 0）。
- 工作原则 8（`investigation.prompt.repeat_branch_rule`）**不在本次消融范围内**：它是上一轮已固化的冻结条目，两臂都保留。
  所以本次对照测的是「第 4 项新加的两段通用步骤」，不是整个规则层的历史累积。

## 4. 判定线（跑之前登记，跑完不许改）

- **有效**：ON 组 3 次里 ≥2 次真的读到了「真正写入这条记录的方法」及其去重/幂等判断分支，且最终答案的成因句
  要么给出该机制、要么明确写「成因尚未定位」。——措辞怎么说不算分。
- **无效**：ON 组工具调用分布与 OFF 组逐项相同（判定分支相关字段 0 次出现）。→ 提示词级强制步骤无效，
  下一步不再加字，改为工具层（强制读取）或复核层（把「缺这条分支」直接当复核意见）。
- **不能判定**：ON 组有的读、有的不读。→ 不加钱继续跑，先查是不是证据包或工具描述的问题。
