## 本轮做了什么

### 代码同步不再闪 cmd 窗口
`server/src/codegraph/sync_manager.ts` 原来用 `promisify(exec(命令字符串))`，
`child_process.exec` 一律经 shell，Windows 上就是 `cmd.exe /c`。
服务端被接棒服务/relauncher 拉起时没有控制台，Windows 给每个 cmd 新开一个可见控制台，
一次同步 18 个仓库 × 六七条命令，屏幕上闪一百多个窗口。
改成 `execFile('git', args)` 直接调 git.exe。
顺带修掉一个隐藏问题：cmd.exe 把 `^` 当转义符，
`git rev-parse P1.0.9^{commit}` 传进去实际变成 `P1.0.9{commit}`，标签比对一直是错的。

### /admin/feishu 内新增服务端控制台
- **运行状态**：服务端（PID/时长/cwd/端口/复核模式/推理档位/上下文/代码库路径/调度模型）、
  飞书桥、在途排查、重启进展，一屏可见。
- **启停**：飞书桥 start/stop/restart；服务端 restart/stop/start。
  有在途任务时接口先拒绝，确认后才放行——`start_production.ps1` 的注释早就写明
  "看到任务在跑仍强行重启"会打断同事的排查。
- **可视化配置**：52 个配置项按 9 组展示，密钥只写不读（只显示"已配置 N 字符"），
  保存前自动备份 .env，写后回读校验，失败自动回滚；重复键一次对齐；
  编码损坏（含 U+FFFD）直接拒绝写入。
- **MCP 服务**：自动发现 `tools/mcp-*` 目录，显示状态/PID/入口/传输方式，支持启停；
  http 传输的才能由控制台启动，stdio 的给客户端命令。
- **审计**：所有控制动作写 `server/data/diagnostics/console-actions.jsonl`
  （谁、什么时候、影响了哪些 pid/键），密钥值一律不记录。

鉴权上特意没收监控台那套"任意非空 Bearer 即过"：控制台有写操作，
必须是监控台会话或**校验过的**管理员令牌。

### 停止之后还能点启动
新增 `console_keeper.mjs`——独立于服务端常驻的小进程（默认 8601），
服务端每次启动都确保它在跑（端口被占就跳过）。服务端被停掉后，
页面的启动按钮自动改走它把服务端拉回来。它自己盯脚本 mtime，
发现变了就退出，由服务端 15 秒一次的 ensureKeeper 拉起新版本。

### grafana 日志 MCP 支持 HTTP 模式
`tools/mcp-grafana-logs/index.mjs` 增加 `--http`（默认 127.0.0.1:8930/mcp）。
不加参数时行为和以前完全一致（stdio），ZCode / DSH 现有用法不受影响。
有了 HTTP 模式，控制台才能把它拉起来，客户端也可以改成连 HTTP。

### 飞书群回复默认只发结论
原来群里贴【结论】+【业务信息】+【还需确认】一整篇。现在默认只发结论 + 问题编号，
业务信息只保留取值是链接的（最多 3 条，导出文件的下载链接是交付物本身），
待确认去详情页看。复核未完成的安全提示一定保留——它不是内容，
去掉会让没复核过的结论看起来和复核过的一样。
`FEISHU_REPLY_DETAIL=full` 可回到旧行为。

### 测试与文档
- `tests/env_defaults.ts`：在 .env 之前固定测试默认值，
  阻止生产 `REVIEW_MODE=off` 写进 .env 后污染服务级测试。
- 复核模式 golden 更新（导出规程加入提示词），并新增"差异锁定"断言：
  把导出规程从系统提示里删掉后必须逐字节回到旧快照，防止提示词被悄悄改坏。
- `docs/ineffective-changes.md` 记录三类运维坑：配置丢失被硬编码兜底盖住、
  PowerShell `Set-Content` 写坏 .env 中文、`REVIEW_MODE` 进 .env 污染测试。

### 分享页回归修复（bc0efff）
让群里只发结论后，分享页差点只剩结论：monitor 库存的 `text` 也变成精简文本，
而分享页一直用 `parseAnswerText` 拆 `text`，`businessData` 拆出来是空的。
完整数据本来就在 `answer_json` 的 `answer` 字段里，只是没被用。
改为分享页优先返回 `answer` 结构化字段，只有老数据没有 `answer` 才退回拆 `text`。
用线上链接实测：businessData 12 条、evidenceSummary 9 条（修复前都是 0）。
教训：改输出格式时要把所有消费方列一遍（群里、分享页、监控页、反馈），不能只看直接改的函数。

## 已知限制（未修，按冻结要求不扩大范围）

1. **仅远程图谱配置不可用**：只配 `CODEGRAPH_ENDPOINT` 不配本地 `CODE_REPO_PATH` 时，
   普通图谱调用提前返回，走不到真正的远程 HTTP 分支。本地路径有值时的远程 fallback 保留。
2. **纯空白路径可绕过部分缺配检查**：同步管理器 trim 判空，但图谱工具与启动横幅只看真假。
   当前生产路径有效非空，未声称线上触发。
3. **测试初始化不能隔离继承的父环境模式**：`||=` 只能挡住 .env 注入，
   父 shell/CI 已有的 `REVIEW_MODE` 不被覆盖。必要时测试前显式设置 `REVIEW_MODE=gate`。
4. **签名下载链接没有身份绑定**：转发者可能下载敏感资料（含护照号）。
5. **console_mcp 的进程匹配偏宽**：`commandLine.includes(service.name)` 可能命中同名路径，
   当前只有一个 MCP 服务，未触发。
6. **进程匹配的分隔符约定不一致**：手工 taskkill 类操作要注意 `feishu/main.ts` 与
   `feishu\main.ts` 的差别（本次排查时误杀过一次接棒服务，已自动恢复）。
7. **`server/dist` 比源码旧**：`npm start` 会跑旧代码，需先 `npm run build`，或用 tsx 命令启动。
8. 公网 `/admin/` 未在 nginx 放行，监控台只能本机访问（有意为之，见 clean-20261104）。

## 启动方式

    cd D:\web_pro\xkang-tui\server
    node --import tsx src/index.ts

服务端起来会自动拉接棒服务（8601）。飞书桥单独起：

    cd D:\web_pro\xkang-tui
    node --import tsx server/src/feishu/main.ts

或在 `/admin/feishu` 控制台点「启动飞书桥」。一键起全部用
`scripts/start_production.ps1`（带在途任务保护与启动自检）。
必须在 `server\` 目录起服务端，否则会连到另一份库。
