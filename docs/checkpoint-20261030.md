## 已确认但本检查点不修复的事项

1. **格式通过可以绕开内核原有证据安全检查。**
   当前 off 模式仍传入 review 回调，格式通过即 accepted。内核在后面的“全部查询失败 / 未执行动作 / 结果不完整”检查前直接 finish。
   离线复现：同样的查询失败结果，不挂回调会拒绝确定性结论；挂等价的格式回调会发布模拟的“已收款”。
   运行 `node --import tsx scripts/eval/publication_path_probe.mjs` 可重现。本脚本只使用内存里的假模型和假工具，绝不触网。
   这只证明发布路径存在旁路，不表示已经证明某条线上错误由它造成。
2. **故障类型在最后输出处被合并。** 模型空正文、网络异常、JSON 错误、公开内容校验失败，可能最终都成为同一“未形成业务结论”文案。格式校验失败不等于业务事实未查到。
3. **时限不是完整流的硬截止。** 内核在循环安全点检查预算；模型调用的建连超时不等于从收到响应头到读完流的总时限。需单独验证流持续输出或不结束的场景。
4. **号码检查不是实体关联验证。** 普通字符串命中（包括仅写在待确认中）也算通过；格式反馈同时要求“不再调用工具”与号码反馈要求“补查”时存在相互冲突。
5. **现有评测不足以证明模型已到能力上限。** 旧批次包含提示词、工具权限、运行表面、输出预算、并发度与数据时点差异；经过调优或人工讲解的案例不是留出集。
